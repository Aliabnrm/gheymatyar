# سند محصول

## خلاصه

قیمت‌یار یک وب‌اپ B2B برای عمده‌فروش‌هایی است که فهرست قیمت تأمین‌کنندگان را از Excel، PDF، عکس و پیام دریافت می‌کنند. نقطه ورود محصول، تبدیل دو نسخه Excel به یک گزارش تغییر قابل اعتماد است.

نام قیمت‌یار موقت است و تصمیم برند نهایی نیست.

## بازار شروع

- صنف: تجهیزات شبکه و دوربین مداربسته
- جغرافیا: تهران
- کاربر اصلی: مالک، مدیر فروش یا اپراتور قیمت
- اندازه اولیه مشتری: ۲ تا ۲۰ کاربر و ۵۰۰ تا ۲۰٬۰۰۰ قلم کالا

این صنف به دلیل کد کالای پرتعداد، قیمت‌های وابسته به واردات، پیش‌فاکتورهای پرتکرار و حساسیت حاشیه سود انتخاب شده است.

## مسئله

با رسیدن فایل جدید، کاربر باید دستی بفهمد:

- کدام کالا اضافه یا حذف شده است؛
- کدام قیمت تغییر کرده است؛
- آیا واحد فروش یا تعداد داخل بسته عوض شده است؛
- آیا پیش‌فاکتورهای قبلی هنوز معتبرند؛
- و کدام قیمت باید مبنای فروش بعدی شود.

یک خطای کوچک می‌تواند باعث فروش زیر قیمت، از دست رفتن سود یا بی‌اعتمادی مشتری شود.

## Job to be Done

وقتی تأمین‌کننده نسخه جدید لیست قیمت را می‌فرستد، می‌خواهم در چند دقیقه تغییرات مهم را ببینم و پس از بازبینی، نسخه درست را مبنای فروش کنم؛ بدون اینکه مجبور باشم صدها ردیف را دستی مقایسه کنم.

## وعده MVP

دو نسخه XLSX یک تأمین‌کننده را بارگذاری کن و تغییر کد، نام، برند، واحد، تعداد بسته، موجودی و قیمت ریالی را دقیق ببین.

## جریان اصلی

1. ورود به حساب و بازیابی سازمان جاری از نشست امن.
2. انتخاب تأمین‌کننده فعال و بارگذاری فایل XLSX قیمت.
3. اعتبارسنجی امنیت container و ساختار فایل.
4. نگهداری فایل اصلی و اتصال آن به سازمان و تأمین‌کننده.
5. استخراج و ذخیره اتمیک ردیف‌های استاندارد به‌صورت Import Draft.
6. نمایش تاریخچه، ردیف‌ها یا خطای مسدودکننده Import ناموفق.
7. بازبینی انسانی تغییرات نسبت به آخرین نسخه ثبت‌شده و ساخت صریح یک snapshot تغییرناپذیر.
8. در جریان مستقل مقایسه، انتخاب نسخه قدیم و جدید و نمایش تغییرات چندبرچسبی.

در pilot فعلی، ثبت‌نام اولیه User، Organization و نقش OWNER را هم‌زمان می‌سازد.
ثبت‌نام عمومی production قابل خاموش‌شدن است و مالک اولیه با command امن onboarding
ساخته می‌شود. دعوت عضو، تعویض سازمان و مدیریت نقش در این برش نیست.

مدیریت تأمین‌کننده و Import پایدار فعال است: OWNER می‌تواند نام تأمین‌کننده را
ثبت، ویرایش و بدون حذف تاریخی غیرفعال کند. OWNER و OPERATOR می‌توانند فایل قیمت
را برای تأمین‌کننده فعال بارگذاری و تاریخچه Import، مشخصات فایل و ردیف‌های
استخراج‌شده را مشاهده کنند. Import موفق فقط `DRAFT` قابل بازبینی است و هیچ قیمت،
نسخه یا فایل به‌صورت خودکار approved نمی‌شود.

## داستان‌های کاربر مرحله اول

- به‌عنوان مدیر فروش، می‌خواهم دو فایل را مقایسه کنم تا تغییرات را سریع ببینم.
- به‌عنوان اپراتور قیمت، می‌خواهم کد تکراری یا قیمت نامعتبر را قبل از استفاده پیدا کنم.
- به‌عنوان مالک، می‌خواهم تغییر تعداد بسته جدا از درصد قیمت مشخص شود تا برداشت اشتباه نکنم.
- به‌عنوان کاربر فارسی، می‌خواهم مبلغ‌ها با جداکننده هزارگان و برچسب ریال نمایش داده شوند.
- به‌عنوان اپراتور قیمت، می‌خواهم فایل اصلی و ردیف‌های استخراج‌شده پس از refresh
  باقی بمانند تا منبع هر داده و خطای Import را پیگیری کنم.

## معیارهای پذیرش

- فایل ماک V1 و V2 بدون اصلاح دستی استخراج شوند.
- شمارش مرجع ۲ کالا اضافه، ۲ حذف، ۱۸ تغییر قیمت، ۲ تغییر فقط اطلاعاتی و ۲ بدون تغییر باشد.
- تغییر pack size کالای ACC-RJ45-CAT6-100 پرخطر نمایش داده شود.
- هیچ مبلغ float یا تومان وارد مدل دامنه نشود.
- خطای فایل، قیمت، کد تکراری و ستون گمشده پیام قابل فهم فارسی داشته باشد.
- کاربر بتواند فقط با مرورگر فرایند را کامل کند.
- فایل unsafe هیچ resource پایداری نسازد؛ خطای کیفیت داده به‌صورت Import ناموفق
  ثبت شود و هیچ مجموعه ردیف ناقصی باقی نماند.
- مشاهده یا بارگذاری Import با UUID نباید مرز سازمان را دور بزند.

## معیارهای موفقیت پایلوت

- دقت فیلدی کد، نام، واحد، pack size و قیمت در فایل‌های ساختاریافته حداقل ۹۹٫۵٪.
- تشخیص ۱۰۰٪ تغییر قیمت برای کدهای معتبر مشترک.
- زمان بازبینی فایل ۱۰۰۰ ردیفی کمتر از پنج دقیقه برای کاربر آشنا.
- حداقل سه کاربر هدف فایل واقعی خود را آزمایش کنند.
- حداقل یک تعهد تجاری واقعی: پرداخت پایلوت، قرارداد آزمایشی یا زمان مشخص برای استقرار.

## مدل درآمد فرضی

- هزینه راه‌اندازی برای ورود داده، قالب تأمین‌کننده و آموزش.
- اشتراک ماهانه بر اساس تعداد کالا، کاربر و حجم پردازش.
- بازه فرضی اولیه: ۲ تا ۸ میلیون تومان در ماه؛ قیمت نهایی فقط پس از مصاحبه و پایلوت تعیین می‌شود.

## خارج از محدوده فعلی

حسابداری کامل، انبار کامل، سامانه مؤدیان، اپ بومی، CRM، فروشگاه، پرداخت، OCR، AI Agent خودمختار، قیمت‌گذاری مشتری و پیش‌فاکتور.

## برنامه کشف محصول

1. مصاحبه مسئله‌محور با پنج عمده‌فروش.
2. دریافت حداقل ده فایل بی‌نام از سه تأمین‌کننده.
3. مشاهده فرایند فعلی بدون معرفی راه‌حل.
4. اجرای نمونه مقایسه با فایل واقعی.
5. ثبت زمان، خطا، اصلاح دستی و میزان اعتماد.
6. درخواست تعهد واقعی به جای پرسیدن «آیا دوست دارید؟».

## خروجی Sprint 3

کاربر در جزئیات Import، عنوان تشخیص‌داده‌شده، ستون‌ها و پنج ردیف نمونه را می‌بیند.
OWNER و OPERATOR می‌توانند برگه، ردیف عنوان و نگاشت را اصلاح و یک اجرای جدید
قابل بازبینی بسازند. خطاها شماره ردیف، نام فیلد، code پایدار و پیام فارسی دارند.
الگوی نگاشت اجرای موفق با اقدام جدا ذخیره و برای فایل بعدی همان Supplier استفاده
می‌شود؛ جایگزینی تأیید صریح می‌خواهد. تفاوت قالب با الگو به خطای قابل اصلاح تبدیل
می‌شود و هیچ داده مبهم یا قیمت جاری به‌طور خودکار معتبر نمی‌شود.

## خروجی Sprint 4

کاربر پس از بازکردن Import معتبر، تغییرات آن را با آخرین snapshot ثبت‌شده همان
Supplier می‌بیند: اضافه/حذف، افزایش/کاهش قیمت، metadata و هشدار مستقل تغییر واحد
یا تعداد بسته. ساخت Version فقط پس از تأیید صریح انجام می‌شود و تاریخچه، کالاها و
گزارش تغییر هر نسخه قابل مشاهده است. بازکردن دوباره Import نسخه‌شده، لینک همان
نسخه و baseline تاریخی آن را نشان می‌دهد و ساخت تکراری را پیشنهاد نمی‌کند.

این Version صرفاً ثبت تغییرناپذیر داده بازبینی‌شده است و خودکار Approved یا Current
نمی‌شود.

## خروجی Sprint 5

OWNER می‌تواند آخرین Version آماده بررسی را صریحاً تأیید یا با دلیل رد کند. تأیید،
نسخه را به قیمت جاری Supplier تبدیل می‌کند و قیمت جاری قبلی را به‌عنوان Version
تأییدشده تاریخی نگه می‌دارد. رد نسخه قیمت جاری را تغییر نمی‌دهد. actor، زمان،
یادداشت و Audit Log برای OWNER و OPERATOR قابل مشاهده‌اند و conflict صفحه stale
به‌جای تصمیم خودکار با پیام روشن متوقف می‌شود.
