# ADR 0006: هویت سازمانی تأمین‌کننده و غیرفعال‌سازی نرم

- Status: Accepted
- Date: 2026-09-02

## Context

هر نسخه قیمت آینده باید به تأمین‌کننده‌ای پایدار و متعلق به یک سازمان وصل شود.
تفاوت فاصله، حروف عربی/فارسی و بزرگی حروف لاتین نباید هویت تکراری بسازد. حذف
تأمین‌کننده نیز ارجاع نسخه‌های قیمت آینده را مبهم می‌کند.

## Decision

- Supplier همیشه `organization_id` دارد و queryهای آن با سازمان استخراج‌شده از
  Session محدود می‌شوند؛ client هیچ organization id ارسال نمی‌کند.
- هویت نام در هر سازمان با `(organization_id, normalized_name)` یکتا است.
- نام با NFKC، تبدیل `ي/ك`، حذف فاصله اضافی و casefold نرمال می‌شود.
- حذف سخت وجود ندارد؛ `is_active` وضعیت استفاده را مشخص می‌کند و نام رکورد
  غیرفعال رزرو می‌ماند.
- OWNER اجازه ایجاد، تغییر نام و وضعیت دارد؛ OPERATOR فقط list و detail را می‌خواند.
- UUID ناموجود و UUID سازمان دیگر هر دو `SUPPLIER_NOT_FOUND` می‌دهند.

## Consequences

- دانستن UUID دسترسی میان‌سازمانی ایجاد نمی‌کند.
- race ایجاد یا rename با constraint دیتابیس به conflict پایدار تبدیل می‌شود.
- تاریخچه آینده می‌تواند بدون شکستن FK به Supplier غیرفعال اشاره کند.
- بازاستفاده نام غیرفعال نیازمند فعال‌سازی همان رکورد است.

## Rejected alternatives

- **دریافت organization_id از client:** ناقض tenant isolation است.
- **unique فقط روی نام خام:** تفاوت‌های نوشتاری رکورد تکراری می‌سازد.
- **partial unique فقط برای رکورد فعال:** هویت تاریخی و reactivation را مبهم می‌کند.
- **DELETE فیزیکی:** برای version و audit آینده نامناسب است.
- **اجازه write به OPERATOR:** با least privilege برای master data فعلی سازگار نیست.
