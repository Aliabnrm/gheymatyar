# ADR 0012: مرز مسئولیت UI، وضعیت بررسی و عمر کش نشست

- وضعیت: پذیرفته‌شده
- تاریخ: 2026-10-15

## زمینه

صفحه نسخه و ویرایشگر نگاشت، هماهنگی درخواست‌ها، تأیید انسانی و نمایش را در
کامپوننت‌های بزرگ ترکیب کرده بودند. وجود داده در TanStack Query به معنی معتبر
بودن آخرین دریافت نیست؛ خطای refetch می‌تواند با داده قبلی هم‌زمان باشد.
حذف mutation از کش نیز درخواست درحال‌اجرای آن را متوقف نمی‌کند.

## تصمیم

- ساختار feature-oriented موجود حفظ می‌شود. مدل‌های خالص مالک تبدیل نمایشی و
  سیاست وضعیت‌اند؛ hookها تعامل و درخواست‌ها را هماهنگ می‌کنند؛ componentها
  نمایش و تعامل محلی را نگه می‌دارند. حلقه نمایشی JSX به‌خودی‌خود منطق دامنه نیست.
- گزارش جاری دو مرحله دارد: کشف مبنا و دریافت گزارش pin‌شده. مجوز تأیید فقط
  از گزارش نمایشی موفق و سازگار با همان pin ساخته می‌شود. درخواست اعتبارسنجی
  یک‌ردیفی سوم حذف می‌شود؛ قواعد مقایسه همچنان در بک‌اند باقی می‌مانند.
- خطا، دریافت تازه و وضعیت terminal اجازه تأیید نمی‌دهند. خطا گزارش کش‌شده را
  به‌عنوان گزارش معتبر نمایش نمی‌دهد. شروع بررسی مجدد، صفحه را صفر می‌کند،
  query با همان pin را هم دوباره می‌خواند و وضعیت Target را تازه می‌کند.
- تأیید انسانی به context بررسی‌شده تعلق دارد؛ تغییر یا نامعتبرشدن آن، تأیید
  را باطل می‌کند. بازیابی همان context پس از خطا تأیید قبلی را زنده نمی‌کند.
- همه mutationهای فضای کاری از کنترل generation نشست استفاده می‌کنند.
  خروج، تغییر حساب و 401 ابتدا generation را عوض می‌کنند، readها را cancel
  و کش query/mutationهای غیر Auth را پاک می‌کنند. پاسخ دیررسِ mutation قبلی
  حق پرکردن کش یا گزارش موفقیت ندارد.
- پاسخ 401 حتی با بدنه نامعتبر نشست را نامعتبر می‌کند. epoch شروع درخواست
  مانع خروج نشست جدید به‌دلیل 401 دیررس نشست قبلی می‌شود. این شناسه‌ها صرفاً
  در حافظه‌اند و مدرک authorization یا مقدار قابل ارسال به سرور نیستند.
- schema و hookهای نسخه با facade عمومی قبلی در دسترس می‌مانند؛ فایل‌های داخلی
  مدل پایه، گزارش، تصمیم، query key، خواندن و نوشتن مسئولیت مستقل دارند.
- استایل اختصاصی مقایسه زیر ریشه comparison-page محدود می‌شود؛ tokenها، reset
  و سیاست reduced-motion سراسری باقی می‌مانند.

## پیامدها

مسیرها، endpointها، payloadها، نقش‌ها، معنای مبنا، واحد پول و پایگاه داده تغییر
نمی‌کنند. هیچ dependency، ذخیره‌ساز مرورگر یا state manager جدیدی اضافه نمی‌شود.
لغو عملیات فرانت به معنی rollback درخواست ارسال‌شده نیست؛ مرجع نهایی وضعیت
ثبت‌شده و مجوزدهی همچنان بک‌اند است. React Query واقعی در تست‌های lifecycle
استفاده می‌شود تا mock کردن hookها raceهای کش را پنهان نکند.
