# ADR 0008: نگاشت قطعی و اجرای مجدد بدون تغییر تاریخچه

- Status: Accepted
- Date: 2026-09-06

## مسئله

ImportRun در ADR 0007 یک snapshot فقط‌خواندنی است. اصلاح عنوان یا ستون نباید
ردیف‌ها و خطای اجرای قبلی را بازنویسی کند. نگاشت مبتنی بر شماره ستون نیز با تغییر
قالب تأمین‌کننده ممکن است قیمت اشتباه ولی ظاهراً معتبر استخراج کند.

## تصمیم

- وضعیت‌ها همان DRAFT و FAILED می‌مانند. اصلاح، ImportRun جدید برای همان
  SourceDocument با parent_import_id، actor و زمان می‌سازد؛ هیچ نسخه قیمت ساخته نمی‌شود.
- نگاشت شامل نام برگه، شماره ردیف عنوان و شماره ستون‌های یک‌مبنا است. فقط
  product_code، product_name و price_irr طبق قرارداد قبلی اجباری‌اند.
- پیشنهاد تشخیص، نگاشت استفاده‌شده و شناسه Template استفاده‌شده در snapshot اجرا
  جدا ثبت می‌شوند. پیشنهاد مبهم هرگز استخراج موفق نیست. کاربر می‌تواند برگه،
  ردیف عنوان و ستون‌ها را صریح انتخاب کند.
- Templateها نسخه‌های دارای UUID هستند؛ تنها یک نسخه فعال در scope سازمان و
  تأمین‌کننده وجود دارد. جایگزینی به شناسه نسخه مشاهده‌شده و تأیید صریح نیاز دارد.
  قفل ردیف Supplier و unique index جزئی، race ایجاد/جایگزینی را کنترل می‌کنند.
- Template فقط از اجرای DRAFT موفق با نگاشت ثبت‌شده ذخیره می‌شود. ذخیره Template
  و اجرای مجدد دو عملیات جدا هستند. رکورد Template با actor، زمان و Import مرجع
  و زنجیره parent اجرای اصلاحی، audit اختصاصی این برش را تشکیل می‌دهند.
- اثرانگشت عنوان تمام ستون‌ها (پس از normalization قطعی) در Template حفظ می‌شود.
  تغییر عنوان، ترتیب، برگه یا محل header با TEMPLATE_LAYOUT_MISMATCH مسدود می‌شود؛
  کاربر پیشنهاد تازه را بررسی و اجرای جدید می‌سازد. fallback خاموش مجاز نیست.
- preview حداکثر پنج ردیف، هر سلول حداکثر ۲۰۰ نویسه، و گزارش حداکثر صد خطای
  ردیفی دارد. شمارش کل خطا و قطع‌شدن گزارش صریح است؛ FAILED هیچ ردیفی ذخیره نمی‌کند.
- raw_row تمام ستون‌ها را با کلید موقعیتی یکتا نیز حفظ می‌کند تا عنوان تکراری
  داده ممیزی را حذف نکند. داده پیش از JSONB شدن JSON-safe می‌شود.
- داده تاریخی فاقد snapshot نگاشت با برچسب «ثبت‌نشده» خوانده می‌شود؛ بررسی مجدد
  فایل فقط پیشنهاد است و اجرای تاریخی را تغییر نمی‌دهد.

## پیامدها و گزینه‌های ردشده

ویرایش in-place به‌دلیل تخریب تاریخچه رد شد. نگاشت خودکار صرفاً بر پایه موقعیت
ستون، انتخاب اولین alias و fallback خودکار Template نامعتبر به‌دلیل خطر قیمت
مبهم رد شدند. ETL عمومی، تبدیل تومان، AI، approval و worker به این برش اضافه نمی‌شوند.

## تکمیل قواعد ورودی

پذیرش float با اعشار صفر در parser قبلی با invariant عدد صحیح سازگار نبود و حذف شد.
جداکننده‌های هزارگان فقط با گروه‌های سه‌رقمی معتبر پذیرفته می‌شوند؛ حذف کور
جداکننده که `1,2` را به `12` تبدیل می‌کرد رد شد. این سخت‌گیری دامنه IRR را تغییر
نمی‌دهد و مانع تفسیر مبهم ورودی می‌شود.
